# 跨工具任务交接

v0.1.3 在原有内部子 Agent 联动之外，增加了本机跨 harness 任务交接识别。支持 ChatGPT 桌面版、Codex CLI、Claude Code 和 DeepSeek Harness，四类来源共用覆盖 12 个方向的交接事件接口。

## 自动识别的路径

| 派发方式 | 派发依据 | 交回依据 |
| --- | --- | --- |
| 新启动 `claude -p`、`codex exec`，含后台启动 | 实际父子进程关系及一次性任务分类 | 实际任务退出；非零退出按失败处理 |
| 带任务的交互会话 `claude "任务"`、`codex "任务"`，含新控制台窗口 | 实际父子进程关系及带任务启动分类 | 对应会话第一轮结束；提前关窗为取消 |
| Windows Terminal `wt new-tab` / `wt -w 0 nt`、WezTerm `cli spawn` / `start` | 派发方终端命令及 15 秒内出现的目标程序带任务会话，每次请求仅配对一次 | 对应会话第一轮结束；提前关窗为取消 |
| Herdr `agent prompt` | 派发进程所属 harness 与目标窗格的 agent 类型 | 目标工作结束并回到空闲；未被接受的派发按失败处理 |
| Herdr `agent send-keys` | 目标窗格对应会话开始新的一轮 | 同一轮结束 |
| WezTerm `cli send-text` | 派发进程关系及随后开始的另一类工具会话 | 对应会话这一轮结束 |
| `codex queue --thread` | 被指定的已有会话实际开始处理新消息 | 对应会话这一轮结束 |

Herdr 的 `/model`、`/effort` 等斜杠命令，以及未开启新一轮的权限批准、方向键、Esc 和尚未提交的输入，不作为派任务。桌宠启动前已有进程只作基线，不重放历史交接。极短任务可能被进程观察漏过；其他终端、GUI 或远程派发需要下面的显式事件桥接。

Claude Code 会话按登记的进程号对应；Codex 按启动后新建的会话记录对应。Claude `--bg` 和继续旧会话的 `codex resume` 暂不作为派任务。终端标签的匹配依赖目标程序及时间窗口，在并发启动等情况下仍有识别边界；需要明确关联时可使用下方事件入口。

## 接入其他派发方式

在托盘菜单选择“接入跨工具联动…”，或从源码运行 `node src/handoff.mjs install`，安装配套技能。新建会话或重新加载技能后使用。安装器仅写入各工具的 `agent-musume-handoff` 目录，不修改 AGENTS.md、登录、权限或工具配置；使用自定义配置根目录时沿用对应环境变量，已有未受管理的同名文件会被保护。

命令入口为 `node src/handoff.mjs`：

- `run --from chatgpt-desktop --to claude-code --command claude.exe -p ...`：包装已获授权的一次性任务，确认启动后派发，按真实退出结果回传。
- `started --from claude-code --to chatgpt-desktop`：目标确认接手后上报，保留返回的随机任务 id。
- `delivered --from claude-code --to chatgpt-desktop --id 原id`：结果交还后上报；失败用 `failed`，取消或结果未知用 `cancelled`。

另两类来源编号是 `codex-cli`、`dsh-desktop`。同一任务重试通知沿用 id，不同任务使用不同 id。仅打开窗口、GUI 启动器退出或两个工具同时忙碌不证明交接或完成。技能不授权新增模型调用或其他对外操作。

## 角色与隐私边界

至少需要两只可见、开启协作且来源/助手关系匹配的桌宠；优先由实际来源与目标对应角色演出。任务标识、来源、目标和状态之外的上报字段会被拒绝，本机写接口校验控制令牌。

程序在本机读取进程关系和必要的命令行分类信息，Herdr 提示词仅检查是否以 `/` 开头；不保存命令行、提示词、回复或工具输出，不读取进程环境变量和内存。会话标识仅在内存中用于匹配对应轮次，不应填入上报的随机任务 id。完整读取范围见 [隐私说明](../README.md#隐私)。

自动识别依赖受支持工具的本地进程和记录格式，不能据此承诺识别任意第三方、网页版或云端调度。完成动画表示相关任务/轮次结束，并不证明长期目标全部成功。
